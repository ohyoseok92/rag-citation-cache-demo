# 출처 오류 진단 보고서 예시

> 자체 제작 합성 사례입니다. 고객 시스템에서 수행한 작업이나 납품 실적이 아닙니다. 이 문서는 진단 상품에서 받을 수 있는 결과물의 형식을 보여 줍니다.

## 의뢰 상황과 완료 기준

- 문제: 문서의 허가 기간을 30일에서 45일로 고친 뒤에도 챗봇이 예전 답과 출처 문장을 돌려줍니다.
- 재현 질문: `When do harbor permits expire?`
- 확인 범위: 문서 스냅샷, 답변 캐시 키, 반환 답변과 인용문. 합성 문서 2개와 질문 1개를 사용했습니다.
- 완료 기준: 문서 변경 직후 같은 질문에 새 문장의 45일 답이 나오고, 인용문이 현재 문서에 존재해야 합니다. 같은 질문을 다시 보내면 새 버전의 답변 캐시가 재사용되어도 됩니다.

## 재현 기록

| 순서 | 관찰한 값 | 판정 |
| --- | --- | --- |
| 1. 이전 문서로 질문 | `Harbor permits expire after 30 days.` / 최초 캐시 미스 | 당시 문서와 답변 일치 |
| 2. 문서를 `45 days`로 변경 | 문서 스냅샷 버전 변경 | 새 문서 반영 |
| 3. 기존 캐시 방식으로 같은 질문 | 캐시 히트, 답변·인용문은 `30 days`, `citation_valid=false` | 오류 재현 |
| 4. 문서 버전을 포함한 방식으로 같은 질문 | 캐시 미스, 답변·인용문은 `45 days`, `citation_valid=true` | 이 사례의 수정 동작 확인 |
| 5. 새 방식으로 질문 반복 | 새 답변 캐시 히트, 인용문 유효 | 반복 호출 확인 |

이 표는 [공개 코드의 재현 테스트](https://github.com/ohyoseok92/rag-citation-cache-demo/blob/main/tests/test_demo.py)와 [웹 시연](https://rag-citation-lab-oh6428.oh6428.chatgpt.site/)을 바탕으로 작성했습니다. 웹 시연은 브라우저 안의 자바스크립트 캐시를 사용하며 Python API나 Dragonfly 서버를 호출하지 않습니다.

## 원인과 수정 지점

기존 답변 캐시 키에는 질문과 답변 생성기 버전만 들어갑니다. 문서를 고쳐도 같은 질문의 키가 유지되어, 유효 기간이 끝날 때까지 예전 답변이 반환됩니다. 답변에 붙은 인용문도 현재 문서에서 찾을 수 없습니다.

수정 예제는 정렬된 문서 스냅샷의 SHA-256 해시를 캐시 키에 넣습니다. 문서가 바뀌면 키가 달라져 이전 답변을 재사용하지 않습니다. 답변을 반환할 때 인용문이 현재 스냅샷에 있는지도 검사합니다. 관련 구현은 [캐시·스냅샷 코드](https://github.com/ohyoseok92/rag-citation-cache-demo/blob/main/src/core.py)에 있습니다.

## 인수할 검증 항목

1. 문서 수정 전 질문을 한 번 실행해 이전 답변을 캐시에 넣습니다.
2. 같은 문서 ID의 내용을 바꾼 직후 질문을 다시 실행합니다. 답변과 인용문이 새 문장인지 확인합니다.
3. 반환된 출처의 문서 ID와 인용문을 현재 문서 스냅샷과 대조합니다.
4. 질문을 한 번 더 실행해 새 버전 캐시에서 동일한 답이 나오는지 확인합니다.
5. 답변 캐시 만료와 문서 스냅샷 보존을 각각 확인합니다.

로컬 가상환경에서 단위·HTTP 테스트 11개가 2026-11-13에 통과했습니다. 이 테스트는 가짜 시계와 캐시를 쓰므로 실서버의 동시 업데이트, 검색 품질, 응답 지연을 검증하지 않습니다. 과거 별도의 로컬 Dragonfly 스모크 테스트 기록은 [저장소 README](https://github.com/ohyoseok92/rag-citation-cache-demo#test-without-a-server)에 있습니다.

## 실제 고객 환경에서 추가로 확인할 것

이 예제는 LLM을 호출하지 않고 질문 단어와 겹치는 문서를 골라 문장을 그대로 답합니다. 실제 RAG 챗봇에서는 문서 수집·청크·검색·재순위화·프롬프트·답변 캐시·출처 표시 중 어느 단계에서 이전 정보가 섞였는지 별도로 추적해야 합니다. 문서 버전이 모든 인입 경로에서 갱신되는지, 답변을 만든 검색 결과와 출처 표시가 같은 스냅샷을 보는지 확인해야 합니다. 동시 편집에는 원자적 갱신이 필요합니다.

따라서 이 예시의 통과 결과를 고객 시스템의 정확도 보증으로 옮겨 적지 않습니다. 실제 의뢰에서는 비식별 재현 자료를 먼저 확인하고, 합의한 오류 한 건에 대한 원인·수정 가능 범위·재검증 결과를 따로 기록합니다.
